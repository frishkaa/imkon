# IMKON — career-ecosystem platform for vulnerable youth (Tajikistan)

A need-centric platform that matches vulnerable youth to opportunities
(scholarships, free courses, legal/health help, volunteering — and, for 18+,
jobs/gigs/freelance), builds a gamified career roadmap (**Роҳи Ман**), issues a
source-verified trust profile (**Паспорти Эътимод**), and lets users share a
live profile + export a PDF résumé. **Minor protection runs first in all
matching logic.**

Trilingual UI (**EN / Русский / Тоҷикӣ**, live language switch). MVP, demoable end to end.

**v2 design** — clean "Minimal-Tech" (Inter, indigo `#5B5BD6`, lots of whitespace), ported from the
attached `tokens.css`/`components.css`/`index.html`. Highlights: expanded registration (account +
10 structured questions incl. **"what you're skilled in" → technologies** like C++/Python/Figma and
**spoken languages + levels**); a **Duolingo-style roadmap** (winding path ⇄ draggable graph);
**company logos + grouped vacancies** (Alif, Zypl.ai, Babilon-T, MegaFon, Spitamen, OSON, DC Tech);
a **résumé-style profile**; and **AI "improve with AI"** on bio / résumé / gig descriptions.
The DeepSeek roadmap quality is benchmarked by a 10-profession judge panel (see below).

## Architecture

```
Imkon/
├─ backend/            FastAPI + SQLAlchemy 2 + Postgres (psycopg3)
│  ├─ app/
│  │  ├─ config.py         settings + the ONE LLM provider switch
│  │  ├─ models.py         full schema (15 tables)
│  │  ├─ matching/engine.py  apply_legal_filter (FIRST) + need-centric score
│  │  ├─ ai/llm_client.py  provider-agnostic: deepseek (dev) | local Qwen (prod)
│  │  ├─ ai/{dialog,resume,roadmap,rag}.py
│  │  ├─ security/         AES-256-GCM fields, argon2, HMAC tokens, rate-limit, access
│  │  ├─ services/         trust, verification, share, pdf, notifications, seed, synthetic
│  │  └─ routers/          all REST endpoints
│  ├─ alembic/         migrations (initial schema autogenerated)
│  ├─ db/rls_policies.sql  production Postgres Row-Level-Security
│  └─ tests/           pytest suite (legal-filter property test, flows, security, AI)
├─ frontend/           React + Vite + TypeScript (mobile-web, the design)
│  └─ src/screens/     24 screens incl. the gamified roadmap path
├─ telegram_bot/bot.py Telegram bot (need-centric; OFF without a token)
├─ dashboard/          Streamlit anonymized service-deserts dashboard
├─ docker-compose.yml  local Postgres
├─ api.txt             DeepSeek dev key (gitignored, read at runtime)
└─ .env                config (gitignored)
```

### The AI provider switch (dev ↔ prod) — ONE line
All model calls go through [`backend/app/ai/llm_client.py`](backend/app/ai/llm_client.py).
Flip in `.env`:
```
LLM_PROVIDER=deepseek   # DEV  — synthetic data only, key from api.txt, OpenAI-compatible
LLM_PROVIDER=local      # PROD — local Qwen 3.5 9B / Qwen 2.5 14B via Ollama; NO data leaves the server
```
Same prompts, same JSON contracts for both. Every AI call has a hardcoded
fallback so a model/network outage never breaks a request.

> Dev note: the public DeepSeek API serves `deepseek-chat` (a large model), not a
> 9–14B dense model. Prompts are kept simple + strict-JSON to keep behavior close
> to the local 9–14B prod target; re-test on Qwen before production.

## Quick start

Prereqs: Docker, Python 3.11+ (tested on 3.14), Node 18+.

```bash
# 1. Postgres (local dev DB on :5433)
docker compose up -d

# 2. Config — copy and (optionally) edit. A real .env with a generated AES key
#    is already present; .env.example documents every variable.
cp .env.example .env            # if you don't already have .env
# put your DeepSeek key in api.txt (already present here)

# 3. Backend
cd backend
python -m venv .venv && ./.venv/Scripts/python -m pip install -r requirements.txt   # (Scripts on Windows; bin on *nix)
./.venv/Scripts/python -m app.init_db          # create tables + seed (idempotent)
./.venv/Scripts/python -m uvicorn app.main:app --port 8000
#   API at http://localhost:8000   ·   docs at /docs

# 4. Frontend
cd ../frontend
npm install
npm run dev                      # http://localhost:5173
```

> If port 8000 is taken on your machine, run uvicorn on another port (e.g. `--port 8010`)
> and set `frontend/.env` → `VITE_API_BASE=http://localhost:8010`. (This repo's
> `frontend/.env` already points at 8010 because 8000 was occupied during the build.)

### Optional surfaces
```bash
# Telegram bot (stays off unless TELEGRAM_BOT_TOKEN is set in .env)
./backend/.venv/Scripts/python telegram_bot/bot.py

# Streamlit dashboard (gov/donor, anonymized) — install its deps first
./backend/.venv/Scripts/python -m pip install -r dashboard/requirements.txt
./backend/.venv/Scripts/python -m streamlit run dashboard/streamlit_app.py
```

### Migrations (Alembic)
```bash
cd backend
./.venv/Scripts/python -m alembic upgrade head      # apply schema
./.venv/Scripts/python -m alembic revision --autogenerate -m "msg"   # new migration
```

## Core domain rules (non-negotiable)
1. **`apply_legal_filter(age, item)` runs FIRST.** Under 18 → never jobs / internships /
   gigs / tasks / employment-required items, and no work questions. Enforced in the
   matching engine, in registration (work needs stripped), and in earning endpoints.
2. **Need-centric scoring.** Education level is a *filter*, never a bonus. NEET and
   migrant-child status *raise* the score.
3. **Verification from the source.** A user cannot self-verify; only a confirmed org
   (school/employer/university) confirms a claim.
4. **Trust Score = growth, not origin.** Sum of verified-achievement weights; no prestige bonus.
5. **Data minimization + residency.** `phone`/`full_name` AES-256-GCM encrypted at rest;
   minors store minimal data; the dashboard uses anonymized aggregates only; prod DB
   stays in Tajikistan (Babilon).

## Demo script (the two "wow" moments + the loop)
1. **Register** as a 15-year-old → feed shows courses/scholarships/help, **never** work.
   Register as a 20-year-old NEET → work section appears.
2. **Роҳи Ман:** Profile → "Build my path" → type a goal → AI builds a 5–8 step
   zigzag map (done ✅ / current / locked) with free-first resources.
3. **Паспорти Эътимод (live loop):** on the path, "Request verification" → choose
   *Ilmhona* → open `/org` in a **second window** → log in (`org@ilmhona.tj` /
   `ilmhona123`) → **Confirm** → the step lights up ✅, Trust Score rises, achievement
   appears on the profile.
4. **Share:** Profile → Share → open the public link / download the PDF résumé (with QR).

See [docs/BUTTON_CHECKLIST.md](docs/BUTTON_CHECKLIST.md) for every wired action.

## Testing
```bash
cd backend
APP_ENV=test ./.venv/Scripts/python -m pytest -q
```
Includes: the 4 spec profiles over the full catalog, an **800-synthetic-minor**
property test (zero work leakage), a **300-user DB-scale** stress test, registration
edge cases + SQL-injection string, field-encryption-at-rest, password hashing, auth
enforcement, the full verification→trust→roadmap loop, share/PDF, and AI robustness
(malformed JSON / outage → fallback). Generate large synthetic data any time via
`POST /dev/synthetic?users=N`.
